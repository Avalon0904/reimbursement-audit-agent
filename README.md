# 报销合规审核 Agent

面向中小公司报销场景的合规审核智能体。设计原则一句话：**能确定性判的绝不让模型判，模型只负责读图与边界喊停。**

---

## 为什么做

中小公司财务多为 1–2 人兼岗，人工核对报销单与制度，单均 5–10 分钟，且存在四类结构性痛点：

- **机械核对占满时间**：贴票、对制度、录台账全是重复劳动
- **擦边案例没人敢拍板**：压线金额、类目存疑，放行怕担责、驳回怕误伤
- **伪造与重复报销防不住**：肉眼看不出真伪，也看不出跨单连号
- **错误代价不对称**：误判放行是资金损失，该转人工没转是信任崩塌

裸 VLM 方案在这三件事上存在**原理性缺陷**（实测见下），这也正是 Agent 存在的理由。

---

## 架构

```
一张发票 = 一个图实例（thread）

ocr(GLM-4V-Flash 免费档)
   │
   ├─ conf_gate ──┬─→ escalate_field（低置信字段，k3 重抽，≤2 次）
   │              ├─→ rule_check（纯 Python，0 token）
   │              ├─→ gate_lowconf（重抽耗尽 → 转人工）
   │              └─→ fuse（步数 25 / token 50K 熔断 → 出审计报告）
   │
   ├─ rule_check ─→ verify（发票查验，fail-closed）─→ ledger_check（跨单查重）─→ record / reject
   │
   └─ human_gate（interrupt 真挂起）─→ 批复 ─→ Command(resume) 续跑
```

**四层防御**（每一层都在消融里被单独切过）：

| 层 | 做什么 | 为什么必须有 |
|---|---|---|
| 1. 规则校验 | 价税勾稽、连号、限额、类目一致性、时限 | 确定性、0 token、同单同判 |
| 2. 发票查验 | 真伪核验（mock 服务模拟政务接口） | **裸模型物理上看不见查验库** |
| 3. 台账查重 | 跨单连号 / 重复报销 | **单次调用没有跨单记忆** |
| 4. LLM | 只负责读图、边界喊停 | 概率模型不该做确定性判断 |

制度条款做成 mini RAG：13 条规模，**刻意砍掉向量腿**（判为过度设计），用 BM25 + 同义词扩展；条款带版本生效区间，按费用发生日过滤。

## 评测结果

评估集：**60 单**（清晰 30 / 模糊 15 / 对抗 15，seed=42 可复现；对抗样本故意过采样到 25%，报告中按真实频率加权）。

### 分层判定准确率

| 配置 | 常规（45） | 对抗（15） |
|---|---|---|
| ① 裸 VLM 基线 | 93.3% | 53.3% |
| ② 完整系统 | **100%** | **93.3%** |

对抗 +40pp 的来源可逐单拆解：**伪造 +4（1→5）、压线 +1、连号 +1**；张冠李戴与超大额本来就对，一分未涨——说明提升不是调 prompt 调出来的，是补上了结构性缺失的能力。

### 分类型召回 / 精确率

| 类别 | 真值数 | 基线召回 | 基线精确 | 完整系统召回 | 完整系统精确 |
|---|---|---|---|---|---|
| 通过 | 25 | 88.0% | 91.7% | 100% | 96.2% |
| 拒绝 | 30 | 80.0% | 100% | 96.7% | 100% |
| 转人工 | 5 | 100% | **41.7%** | 100% | **100%** |

> 基线转人工 12 单里 7 单是误转（精确率 41.7%）——**意味着财务仍需逐单复核，系统形同虚设**。完整系统转人工 5 单全部正确。

### 成本与延迟

| 配置 | token p50 | 延迟 p50 / p95 |
|---|---|---|
| ① 裸 VLM | 3184 | 39.8s / 81.0s |
| ⑦ 免费 VLM 首过 + 旗舰兜底 | **1161（-64%）** | **4.2s / 6.4s** |

### 七组消融（逐组件边际贡献）

| 消融 | 判定变化 | 结论 |
|---|---|---|
| ③ 去规则 | 对抗 93.3 → 53.3 | **规则层是命中率第一支柱**（+40pp） |
| ④ 去检索 | 判定零变化，引用贯通 100% → 0 | **检索的价值纯是可审计性** |
| ⑤ 去分层 | 判定全等，token 反而更省 | "双档省钱"假设被 token 口径证伪 |
| ⑥ 去容错链 | 判定全等 | 零触发——是保险费，不是利润来源 |
| ⑦ 异构双档 | 判定全等，token -64% | 以真价差形态复活，成新 Pareto 最优点 |

> ⑤ 是最有价值的一刀：**我的成本假设被自己的实测推翻了。** 真正省钱的不是"便宜的模型"，是"免费的模型"。

## 快速开始

```bash
cd project2/agent
pip install -r requirements.txt      # fastapi / uvicorn / langgraph / langgraph-checkpoint-sqlite / requests

# 配置环境变量后启动
python server.py
# → http://127.0.0.1:8010
```

页面三功能区：审单台（SSE 逐节点进度）/ 待审队列（批复后续跑）/ 台账与审计日志。

## 已知局限

1. **golden set 是合成数据**（PIL 渲染 + degrade），非真实拍照件；真实场景的 OCR 难度更高。
2. **SqliteSaver 单连接**，图执行加了全局串行锁——为正确性牺牲了吞吐，上生产要换 Postgres checkpointer。
3. **免费 VLM 的自评置信度恒为 1.0**，无区分度；真实拍照件上它犯错时不会有人喊停。缓解方案（字段级校验和做客观置信信号）已设计、未实现。
4. **模糊分层压不出容错链**，⑥刀零触发是"没被压测"，不是"没价值"。
5. **制度只有 13 条**，向量检索判为过度设计；规模上去要加向量腿。
