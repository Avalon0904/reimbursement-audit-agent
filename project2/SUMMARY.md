# 项目二 · 报销合规审核 Agent — 阶段总结（截至 2026-10-22）

> 覆盖范围：选题定案 → 阶段 0 → 评估集封版 → 裸 VLM 基线 → 分层方案定案 → State schema。
> 一句话状态：**评估侧全部封板，工程侧完成 schema，LangGraph 主干开工在即。**

## 一、业务痛点

20~200 人公司的财务/行政（1~2 人兼岗）人工核对报销单据与制度，单均 5~10 分钟：

1. **机械核对占满时间**：逐张比对发票字段、限额、条款，枯燥且量大；
2. **擦边案例没人敢拍板**：压线金额、类目存疑的单据，放行怕担责、驳回怕误伤；
3. **伪造与重复报销防不住**：肉眼无法核验发票真伪与跨单连号；
4. **错误代价不对称**：误判放行=公司真金白银损失+审计风险；误判驳回=员工体验；该转人工没转=系统信任崩塌。

目标：Agent 自动完成"识别→合规审核→录入"，存疑/大额按制度转人工；机器吃下确定性工作，人只处理真正需要判断的少数单。

## 二、场景选型（被否候选与理由）

| 候选 | 判定 | 核心理由 |
|---|---|---|
| 发票识别录入（原版） | 升级 | 可判定性满分但 Agent 含量薄 → 加厚为"合规审核" |
| 竞品周报 | 否 | 真值不可判定、外部依赖高、评估不可复现 |
| 深度调研 | 备 | 长程压力真实，但评估绕不开 judge，与"评估优先"冲突 |
| GitHub 仓库分诊 | 否 | 外部仓库天天变，违反"双机复现"纪律 |
| 数据分析 | 否 | 代码沙箱是独立大坑，demo 烂大街 |
| 事实核查 | 备 | 判定性最强、叙事好，但 Agent 厚度不如报销场景 |
| **报销合规审核** | **选** | 判定可程序化、Agent 决策分叉天然、成本分层是业务本身的分层、化工特色条款提供领域区分度 |

## 三、技术选型与架构决策

| 决策 | 选择 | 理由（含被否方案） |
|---|---|---|
| 编排框架 | LangGraph 1.2.16 | Agent 本质是状态机：分叉/回退/中断需要图模型；裸 ReAct 循环不可测不可控 |
| 架构频谱 | 中间：主干钉死+岔路交 LLM+危险操作 interrupt | 全写死=不智能；全自主=不可靠不可复现 |
| 校验主力 | 纯 Python 规则校验器（零 LLM） | 能确定性判的绝不让概率模型判：可靠、免费、可消融 |
| 模型分层 | 规则层(0 token) → k2.6(OCR 首过) → k3(疑难复核/条款引用) | 探针实测：k2.6 视觉可用且轻推理(~248 token/单)；DeepSeek 无视觉被否；省的是算力结构不是单价 |
| 任务粒度 | 一票一图实例（thread） | 被否：大图顺序批处理——单票 interrupt 会阻塞全批次 |
| 中断恢复 | checkpointer(SQLite) 快照 + 人工批复写回 State | 挂起=持久化的正常状态，恢复后从断点续跑；知识检索类节点恢复后重跑防旧快照 |
| 真伪核验 | 查验 mock 服务（MCP server） | 真实世界即政务外部 API，协议集成故事成立 |
| 台账 | SQLite + 自包 MCP server | 连号/重复检测需要跨单记忆——单次调用原理上做不到 |
| 制度知识 | mini RAG，条款带版本与生效区间，按费用发生日过滤 | 改制度=新增版本非覆盖；结论记版本指针可审计回溯 |
| 失败策略 | fail-closed：查验失败默认转人工 | fail-open 是真实事故常客 |
| 熔断 | 步数 25 / 无进展 3 步 / token 50K 硬顶，触发即优雅退出+报告 | 防死循环烧光预算；打转判定用关键字段哈希而非全量比较 |
| 双维度计量 | token 与延迟同按节点分桶（State `token_usage[节点]={prompt,completion,model,latency_s}`） | 成本能归因到节点，延迟也要能；时间三口径分离：节点延迟（定位慢点）/ 机器耗时（性能验收，扣人工等待）/ 端到端墙钟（仅业务参考） |

## 五、裸 VLM 基线结果（kimi-k3 单轮一把梭，60/60 零失败）

| 口径 | 字段准确率 | 判定准确率 | 条款挂载 |
|---|---|---|---|
| 清晰（30） | 1.000 | 0.900 | 0.900 |
| 模糊（15） | 1.000 | 1.000 | 1.000 |
| 常规合计（45） | 1.000 | 0.933 | 0.933 |
| **对抗合计（15）** | 1.000 | **0.533** | **0.200** |

对抗分型：压线 0.667 / **连号 0.000** / 张冠李戴 1.000（条款 0.000）/ 超大额 1.000 / **伪造 0.200（5 单漏 4）**。转人工召回 100%（预测 50~60%，落空认账：k3 胆小，压线合规也转人工）。成本 p50=3184 token/单；延迟 p50=39.8s / p95=81.0s（并发 5 墙钟，单请求口径）。

**三大原理级发现 = 完整 Agent 的主战场**：① 无查验工具则伪造物理不可见；② 单次调用无跨单记忆，连号原理性不可能；③ 判定对但条款挂错——检索+引用指针的价值锚点。

## 八、LangGraph 主干进展（2026-10-22）

**环境**：用户全局 conda Python 3.14.6 + langgraph 1.2.16（checkpoints 走 SqliteSaver）。k2.6 上岗冒烟 72/72 字段全对、单均 1698 token、p50 17.5s（约为 k3 的一半），分层方案闭合。

**v0.1 最小主干**（`agent/graph.py`）：OCR(k2.6)→规则校验(0 token)→三路由，3 张清晰单 3/3；checkpointer 持久化、节点级 token+延迟双维计量、机器耗时/墙钟分离全部落地。

**v0.2 主干**：接入查验节点（fail-closed）+ 台账连号检测，流水线：`ocr → rule_check → verify → ledger_check → record/reject/review/escalate`。扩展范式：新能力以数据形式流入旧节点（查验命中→追加 rule_violations→复用 reject），不改旧节点。

对抗切片验证（8 单）：

| 目标 | 基线 | v0.2 | 说明 |
|---|---|---|---|
| 伪造拦截 e×5 | 1/5 | **5/5** | 查无此票/已作废/金额不符，确定性拦截+查验证据 |
| 连号检出 b×2 | 0/2 | B02 ✓ | B01 首单时序上无可比对（原理性），B02 被抓时指认撞单→追标；口径：单票级 1/2、**连号组检出率 100%** |
| 正常单不误伤 | ✓ | ✓ | pass 路径走通五节点 |

**v0.3 HITL 真挂起**（escalate/review 从"标记即结束"升级为闭环）：

- 设计：`human_gate` 单节点收口，两路入口殊途同归——`gate_kind` 区分 escalate（权限边界）/ review（能力边界），分开统计；`interrupt()` 载荷=待批快照（票号/金额/系统建议），恢复值=批复 `{action, note, reviewer}` 写回 `human_decision`，按 action 分流 record/reject。
- 跨进程验证（D01/D02）：进程 A 挂起写入 `pending_queue.json` 退出 → 进程 B `--decide <thread_id>` 复活续跑。D01 批准→录入台账（理由带批复人批注），D02 驳回（批复进 reason）；队列处理完自动出列归零。
- 时间口径实锤：机器耗时 21.6s 为纯机器段，人工等待按三口径设计扣除。

**v0.4 制度检索 mini RAG**（`agent/policy_store.py`）：

- 规模判断：13 条制度上 Milvus 是过度设计 → 项目一混合检索的 **BM25 腿裁剪复用**（jieba+rank_bm25），向量腿位置与升级理由预留。
- 双岗位：`cite()` 条款号→原文指针+版本（按费用发生日过滤生效期，4.2 条承诺兑现）；`search()` 自由查询 BM25 top-k。
- 检索工程曲线（白捡的实验）：裸 BM25 口语查询 **5/8** → 同义词关键词扩展（口语↔制度语映射显式编码）**7/8** → 残余「餐饮开成办公用品」误中 2.4：词面重叠压过意图，**BM25 原理性盲区 = 向量腿存在理由的实证**。
- 落地：驳回理由带"依据 v1.0 x.y「原文」"，可审计引用贯通（治基线条款挂载 0.200 的病）。

**v0.5 主干收齐**（单字段 escalation + 熔断三件套）：

- 容错链：`conf_gate` 路由——逐字段置信度 <0.7 且重试 <2 → k3 **只重抽低置信字段**（好字段锁死防回归）；重抽一字未变=打转，stall≥2 放弃；耗尽 → gate_lowconf 转人工（fail-closed，不静默放行）。
- 熔断：步数 25 / token 50K 硬顶 → `fuse_node` 生成 audit_report（含已完成节点清单，"转人工兜底"优雅终态，非 crash）。
- 验证双轨（现有模糊度压不出自然触发 → 注入状态直测，不动 golden set）：`test_escalation.py`——路由 5/5；k3 真把模糊件 invoice_code 从 000000000000 重抽为真值（置信度 0.4→0.98）；好字段锁死 ✓；主路径回归无回退。

最终流水线：

```
ocr(k2.6) → conf_gate ─┬→ escalate_field(k3 单字段↺≤2次，打转即弃) → 回 conf_gate
                       ├→ rule_check → verify(fail-closed) → ledger_check → record/reject(带原文引用)
                       ├→ gate_lowconf（重试耗尽→人工门）
                       └→ fuse（步数25/token50K → audit_report）
人工门 human_gate：escalate(权限) / review(查验不可用+低置信) → 挂起→批复→分流
```
