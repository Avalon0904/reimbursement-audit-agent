# Golden Set 构造方案 v0.1

> 配套：制度文档 `policy/报销制度_v1.0.md`；生成器 `scripts/gen_invoices.py`
> 纪律：生成器自动保证"图像 ↔ 真值"一致；人工抽验仍是放行前提。

## 一、分层与分布（60 单）

| 分层 | 数量 | 构成 | 对应一级指标 |
|---|---|---|---|
| 清晰·常规 | 30 | 合规与违规混合（违规含超限额/超时限/抬头不符三类） | 字段准确率 ≥98%、常规判定 ≥95% |
| 模糊·容错 | 15 | 模糊手段：旋转 ±3°、高斯模糊、JPEG 压缩、亮度抖动；合规/违规混合 | 低置信不得静默通过、重试 ≤2 |
| 对抗 | 15 | 见下表 | 对抗判定 ≥85%、转人工召回 ≥90%、伪造拦截率 |

> 实测封版（seed=42，60 单）：常规 45 = 合规 25 / 违规 20（超限 13：2.1×6/2.4×2/2.3×2/3.2×3、超时限 1.1×3、抬头 1.2×4）；对抗 15 = a3/b2/c3/d2/e5；verdict 分布 pass 26 / reject 29 / review 3 / escalate 2。真值一致性校验：零冲突；查验库伪造记录 5（not_found 2 / voided 1 / 金额不符 2）。模糊件肉眼抽验：难但可读 ✅。

对抗子集 15 单分配：

| 样例 | 类型 | 数量 | 真值 | 挂钩条款 |
|---|---|---|---|---|
| a | 压线：住宿 498 / 502（限 500） | 3（合规 1 + 违规 2） | 精准区分，502 驳回 | 2.1 |
| b | 连号：同一人同日两票（号码相邻），分两条目 | 2（一组） | 驳回并合并计额 | 1.5 |
| c | 类目张冠李戴：餐饮票申报"办公用品" | 3 | 存疑转人工（不硬判驳回） | 1.3 + 4.1 |
| d | 超大额：6800 元，其余完全合规 | 2 | 挂起转人工审批（不通过不驳回） | 1.4 |
| e | 伪造三档：查无此票 / 金额不符 / 已作废 | 5（2+2+1） | 驳回 + 附查验证据（**一级指标**） | 1.6 |

## 二、真值 schema（golden_set.jsonl 每行一单）

```json
{
  "invoice_id": "INV-0001",
  "image": "images/INV-0001.jpg",
  "stratum": "clear | blur | adversarial",
  "adversarial_type": "a|b|c|d|e|null",
  "fields": {
    "invoice_code": "011002500111", "invoice_no": "13572468",
    "date": "2026-03-12", "buyer_name": "蓝丸化工科技有限公司",
    "buyer_tax_id": "91330100MA27XT2P4A",
    "seller": "杭州云栖酒店有限公司",
    "items": [{"name": "住宿费", "qty": 1, "price": 471.70, "tax_rate": 0.06, "amount": 500.00}],
    "total": 500.00
  },
  "claim": {"category": "住宿费", "city_tier": 1, "applicant": "张三", "expense_date": "2026-03-12"},
  "verdict": "pass | reject | review | escalate",
  "violated_clauses": ["2.1"],
  "review_reason": "",
  "notes": "对抗 a：压线合规样本"
}
```

verdict 四值口径：**pass** 通过 / **reject** 驳回（须挂条款）/ **review** 存疑转人工复核 / **escalate** 大额转人工审批。review 与 escalate 分开统计（能力边界 vs 权限边界）。

## 三、查验 mock 库（verify_db.json）

- 生成器同步产出：`invoice_no → {status: valid|voided|not_found, total}`。
- 伪造样例通过操控查验库制造（图像上票面金额与库内记录不一致 = 中级伪造），**图像本身保持自洽**——伪造信息只存在于查验库里，这模拟现实：票面是真的图，底账戳穿它。

## 四、放行验收（用户执行）

1. 跑生成器 → 抽 10 张肉眼检查：关键字段可读、版式像发票、模糊件"难但非不可读"。
2. 真值一致性：随机抽 5 单，人工从图上读字段与 jsonl 比对，**任何不一致 = 整批重生成**（生成器 bug，不许手改真值）。
3. 分布核对：分层、对抗类型、verdict 分布与本方案表一致。
4. 条款挂钩核对：每单 violated_clauses 与制度文档条款号对得上。
